WHAT NEBULA IS
A deterministic multi-core Minecraft server on Folia 26.1.2. Redstone/entity physics run
as tasks in a DAG executed across region threads; three-phase ticks
(syncFromNms -> DAG -> syncToNms) over thread-safe CAS state stores. The project's defining
wound is DOCUMENTATION DRIFT: for years docs claimed behavior the code never had. Your
prime directive is honesty. Never claim something works unless YOU verified it THIS cycle.

THE DECISIVE EXPERIMENT: if your change touches the tick pipeline (DAG exec, NMS bridges,
hooks, hasher, capture), a green unit test is NOT proof. Verify on real Folia:
1. Deploy the shaded jar to folia-test-server/plugins/.
2. Start detached (survives the tool call lifecycle):
   cd folia-test-server && setsid ./start.sh > server-run.log 2>&1 < /dev/null & disown
3. Place redstone, run /nebula scan, then TOGGLE it. A static circuit emits no
   BLOCK_UPDATEs; toggling is what exercises the pipeline. RCON:
   mcrcon -H 127.0.0.1 -P 25576 -p nebulatest "<cmd>"
4. RCON block READS (execute if block, data get block) throw NPE on Folia (off-region-thread
   read). Use writes plus server-run.log as ground truth, never reads.
5. Stop the server cleanly (RCON "stop") before finishing the cycle.
